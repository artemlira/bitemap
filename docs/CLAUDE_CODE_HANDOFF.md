# BiteMap — передача контексту Claude Code

Оновлено: 2026-11-06

Цей файл передає контекст іншому агенту, щоб продовжити роботу над BiteMap без
повторного збору історії з чату. Це знімок стану на дату оновлення; перед будь-
якими діями перевір поточний Git, Firebase, CI та Hostinger стан.

## Інструкція для агента, який приймає роботу

1. Прочитай `AGENTS.md`, цей файл і пов'язані документи з розділу «Ключові
   документи».
2. Почни з `git status --short --branch`, `git log -5 --oneline --decorate` та
   `git diff --stat`. На момент передачі робоча гілка `docs/claude-code-handoff`
   створена від `main`; у ній уже є незакомічені зміни з попередньої роботи.
3. Не виконуй `git reset`, `git clean`, `checkout -- .`, масове форматування,
   stash/pop чи масове stage/commit. Не відкидай зміни й не коміть їх усі разом:
   серед них можуть бути незалежні задачі користувача. Спершу розбери кожен
   diff і уточни межі коміту, коли вони неочевидні.
4. Не працюй безпосередньо в `main`. Для коду дотримуйся Git/PR правил з
   `AGENTS.md`; користувач просив вести роботу в основній папці репозиторію, а не
   в окремій копії/worktree.
5. Не публікуй і не деплой зміни без прямого запиту. Після перевірок підготуй
   зрозумілий diff і запропонуй наступний крок.

## Продукт і цілі

BiteMap — двомовний (українська/англійська) сервіс для пошуку водойм і
планування риболовлі, особистих нотаток, фото та звітів спільноти. Користувач
хоче, щоб каталог і сторінки водойм були корисними на кшталт FishMap, але BiteMap
має залишатися самостійним продуктом зі своїм дизайном і текстами.

FishMap дозволено використовувати як орієнтир для структури функцій та як одне
із джерел перевірки окремих локацій. Якщо доступна офіційна інформація —
переважно спиратися на неї. Якщо офіційного джерела немає, можна переказати
відомості своїми словами, чітко позначаючи джерело й неперевірений статус.
Не копіювати каталог або редакційні тексти цілком. Фото брати лише з джерел із
підтвердженим правом повторного використання й показувати авторство, джерело та
ліцензію. Не підставляти перше зображення з Google Images без перевірки прав і
відповідності конкретній водоймі.

Поза поточним обсягом: барахолка, турніри та магазини.

Користувач працює WordPress-розробником, вивчає React і розглядав WordPress як
CMS/адмінку для контенту з Next.js фронтендом. Це поки що ідея для архітектурної
оцінки, а не реалізована чи остаточно затверджена міграція. Поточний застосунок
використовує Firebase; користувач сумнівається в межах безкоштовного тарифу й
хоче розглянути кращу базу/сховище для контенту та зображень. Не починай
міграцію без окремого плану, оцінки ціни, перенесення даних і узгодження
архітектури.

Поки розробка триває, користувач хоче закрити сайт від індексації. У репозиторії
є перемикач індексації через `BITEMAP_SEARCH_INDEXING_ENABLED`; за замовчуванням
він вимкнений. Не вмикай індексацію до окремого рішення користувача.

## Поточна технічна основа

- Next.js 16 App Router, React 19, TypeScript; збірка `next build --webpack`.
- Структура Feature-Sliced Design у `src/app`, `views`, `widgets`, `features`,
  `entities`, `shared`.
- Firebase Authentication, Cloud Firestore і Firebase Emulator Suite.
- Cloudinary для фото з підписаним завантаженням.
- Leaflet / React Leaflet / OpenStreetMap; Open-Meteo для прогнозу погоди.
- `next-intl`, SCSS Modules, Tiptap і DOMPurify.
- GitHub Actions: lint, unit, TypeScript/build, Firestore rules та E2E.
- Hostinger Node.js site, пов'язаний із репозиторієм `artemlira/bitemap`.

Точні інструкції та налаштування дивись у `README.md`,
`docs/architecture.md`, `docs/firebase-setup.md`, `docs/firestore-security.md` і
`docs/hostinger-deployment.md`.

## Основні реалізовані можливості

- Двомовні публічні сторінки та адаптивна навігація.
- Каталог водойм: пошук, регіон/тип/риба, мапа, картки та сторінки водойм.
- Координати, прогноз погоди на 7 днів та орієнтовний індекс активності.
- Firebase email/password і Google authentication.
- Приватні водойми користувача, редагування та публікація для спільноти.
- Фото водойм, звіти про риболовлю, коментарі, реакції, обрані водойми,
  підписки та стрічка активності.
- Статті, WYSIWYG-редактор, адмінські інструменти й модерація скарг.
- Firestore Rules, індекси та локальні emulator/browser flows.
- SEO metadata, sitemap/robots, HSTS, dependency security fix з PR #2.
- Розгортання на Hostinger через push/merge у `main` (але не вважати зелений CI
  доказом успішного Hostinger deploy: перевіряти deployment log і commit).

README та roadmap описують цільовий стан і план ширше за поточний рівень
наповнення даними. Перед тим як називати певну функцію повністю готовою, звір її
з кодом, тестом і розгорнутим середовищем.

## Де зупинилися з каталогом

Остання задача користувача: каталог карток не влаштовував; просив зробити його
ближчим до сторінки водойми FishMap — зі справжніми фото, зрозумілими описами,
видами риб і координатами.

У незакоміченій робочій копії зроблено:

- Додано Русанівський канал як локацію каталогу з координатами `50.43294,
  30.596634`, окремою сторінкою, описом і списком риб зі статусом
  «неперевірено».
- До карток додані локальні фотографії, alt-тексти й підпис автора/джерела/
  ліцензії. На сторінці Русанівського каналу показано три фото.
- Для 14 curated локацій у поточному дереві є 16 фото для 13 локацій; для
  Блакитного озера біля Підгірців відкриту ліцензію не підтверджено, отже фото
  навмисно відсутнє.
- Авторство та ліцензії задокументовано в
  `public/images/fishing-spots/ATTRIBUTION.md`.
- Додано `docs/fishing-spot-catalog-audit.md` як аудит і список покращень.
- В останньому візуальному проході Playwright картки були переглянуті на
  desktop і mobile; фото відображаються. `npm run lint`, `npm run build` і
  `git diff --check` завершилися успішно.

Примітка до перевірок: локальна сторінка показувала помилки підключення до
Firestore Emulator, бо він не працював. Вони не були помилками рендерингу фото.
Перед наступними тестами перевір вільність портів і чи вже не запущений
`npm run emulators`.

   підтвердженого джерела/дати.
4. Розширювати каталог малими перевіреними порціями: спершу конкретні водойми

   перевірці browser flows запускати emulator і E2E окремо, враховуючи Java 21,
