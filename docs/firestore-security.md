# Firestore Security Rules для BiteMap

Профілі та обрані водойми є приватними даними. Авторські водойми мають два
режими: `private` доступний лише власнику, а `published` можна читати кожному,
щоб автор міг поділитися посиланням. Змінювати або видаляти документ з
`user-spots` може лише користувач, чий Firebase `uid` збігається з `ownerId`.

Щоб застосувати їх у Firebase Console:

1. Відкрий **Firestore Database → Rules**.
2. Замінити стандартні правила вмістом файлу `firestore.rules`.
3. Натисни **Publish**.

Після першого входу BiteMap створить документ `users/{uid}` автоматично. Не
створюй його вручну в консолі.

Авторські водойми створюються у верхньорівневій колекції `user-spots`.
Спільнота запитує лише документи з `visibility == "published"`; це важливо,
бо правила Firestore не фільтрують результати запиту самостійно. Власні записи
запитуються окремо за `ownerId`, а змінити `ownerId` під час редагування
неможливо.

Коли додамо загальний каталог водойм у Firestore, правила для `spots` будуть
окремими: публічне читання та обмежений запис. Не відкривай зараз доступ до
всіх колекцій через `allow read, write: if true`.

## Фотографії водойм

`spot-images` — окрема колекція з метаданими фотографій: цільова водойма,
автор, Cloudinary public ID, URL та український/англійський підпис. Автор може
додавати фото до власної водойми, а зареєстрований користувач — до каталожної
або вже опублікованої водойми спільноти. Приватна водойма не приймає фото від
інших користувачів і не показує свою галерею гостям.

Cloudinary Free зберігає зображення за CDN URL. Firestore не віддає метадані
приватної водойми неавторизованим користувачам, але URL не є механізмом
захисту секретних фото. Не завантажуй у MVP конфіденційні зображення; для
повністю приватного медіа пізніше знадобляться signed delivery URLs.

## Звіти про риболовлю

Звіти з публічних водойм бачать усі, а створити, відредагувати або видалити
свій звіт може лише автор. Під час редагування Rules не дозволяють змінити
автора, водойму чи рівень публічності запису. Після змін у `firestore.rules`
завжди встав повний вміст файла у **Firestore Database → Rules** і натисни
**Publish**.

## Підписки на рибалок

Підписки зберігаються у `angler-follows`. ID документа має формат
`{followerId}__{followedId}`. Список підписників доступний для читання, щоб
публічний профіль міг показувати їхню кількість; створити підписку можна лише
від власного Firebase UID, змінювати документи заборонено, а видалити підписку
може лише її автор. Самопідписки не дозволені. Після додавання правил до
`firestore.rules` опублікуй повний файл у **Firestore Database → Rules**.

## Коментарі до звітів

Коментарі зберігаються у підколекції `fishing-reports/{reportId}/comments`.
Їх можна читати лише разом із публічним звітом; додати коментар може лише
авторизований користувач від власного UID. Текст обмежено 1200 символами,
редагування заборонене, видалити коментар може лише його автор. Після оновлення
правил опублікуй повний `firestore.rules` у Firebase Console.

## Реакції

Вподобайки до публічних звітів і фотографій зберігаються у вкладених колекціях
`fishing-reports/{reportId}/reactions/{userId}` та
`spot-images/{imageId}/reactions/{userId}`. Один документ на Firebase UID
забезпечує одну реакцію від користувача на матеріал; авторизований користувач
може додати або прибрати лише власну реакцію. Для зображень реакції доступні
лише в каталозі та для опублікованих водойм спільноти. Після оновлення правил
повторно опублікуй повний `firestore.rules` у Firebase Console.

## Статті та редактор

Статті зберігаються у верхньорівневій колекції `articles`, ID документа
збігається з його `slug`. Відвідувачі можуть читати лише документи зі
`status == "published"`; адміністратор може також читати чернетки, створювати,
редагувати й видаляти матеріали. Початкові статті з коду можна редагувати:
зміни зберігаються як Firestore-перевизначення. Для повернення оригіналу
видали таке перевизначення через кнопку «Відновити оригінал».

Редактор перевіряє наявність документа `admins/{uid}`. Створи його вручну у
Firebase Console для кожного адміністратора (ID документа — Firebase Auth UID;
поля можна не додавати). Правила забороняють створення та зміну документів
`admins` з браузера, тому користувач не може сам видати собі права.

Після публікації правил увійди у BiteMap і відкрий **Редакція** або
`/uk/admin/articles`. Український текст обов’язковий; порожні англійські поля
автоматично використовують українську версію. Чернетки приховані від
відвідувачів. Редактор підтримує форматований текст, списки, посилання та
зображення; час читання обчислюється за українським текстом автоматично.
Завантаження зображень статей використовує Cloudinary API Secret, але сервер
видає підпис лише після перевірки документа `admins/{uid}`.

## Скарги та модерація

Скарги зберігаються у `content-reports`; їх можуть створювати лише
авторизовані користувачі. Підтримуються публічні водойми спільноти, фото,
публічні звіти, коментарі та опубліковані статті. Один користувач не може
повторно створити той самий документ скарги. Чергу `/uk/admin/moderation` та її
зміни можуть читати й виконувати лише адміністратори з документом
`admins/{uid}`. Адміністратор може приховати водойму, звіт або статтю, видалити
фото разом із Cloudinary-об’єктом чи видалити коментар; відхилення скарги не
змінює сам матеріал. Після кожної зміни правил опублікуй повний файл
`firestore.rules` у Firebase Console.
