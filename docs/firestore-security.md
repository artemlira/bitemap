# Firestore Security Rules для BiteMap

Профілі та обрані водойми є приватними даними. Авторські водойми мають два
режими: `private` доступний лише власнику, а `published` можна читати кожному,
щоб автор міг поділитися посиланням. Змінювати або видаляти документ з
`user-spots` може лише користувач, чий Firebase `uid` збігається з `ownerId`.

Щоб застосувати їх у Firebase Console:

1. Відкрий **Firestore Database → Rules**.
2. Замінити стандартні правила вмістом файлу `firestore.rules`.
3. Натисни **Publish**.

Після першого входу BiteMap створить документ `users/{uid}` автоматично. Не
створюй його вручну в консолі.

Авторські водойми створюються у верхньорівневій колекції `user-spots`.
Спільнота запитує лише документи з `visibility == "published"`; це важливо,
бо правила Firestore не фільтрують результати запиту самостійно. Власні записи
запитуються окремо за `ownerId`, а змінити `ownerId` під час редагування
неможливо.

Коли додамо загальний каталог водойм у Firestore, правила для `spots` будуть
окремими: публічне читання та обмежений запис. Не відкривай зараз доступ до
всіх колекцій через `allow read, write: if true`.

## Фотографії водойм

`spot-images` — окрема колекція з метаданими фотографій: цільова водойма,
автор, шлях у Storage, URL та український/англійський підпис. Автор може
додавати фото до власної водойми, а зареєстрований користувач — до каталожної
або вже опублікованої водойми спільноти. Приватна водойма не приймає фото від
інших користувачів і не показує свою галерею гостям.

Додатково застосуй [`storage.rules`](../storage.rules) у **Storage → Rules**.
Вони дозволяють лише зображення до 5 МБ, а приватні фото читає тільки власник.
